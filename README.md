# FileVault Node

لایه‌ی کاموفلاژ **nginx + سایت آپلودسنتر** برای نودهای Xray/Pasarguard.
کل نصب و مدیریت با یک منوی فارسی انجام می‌شود: `sudo fv`

* باز کردن دامنه در مرورگر → یک سایت آپلود فایل انگلیسی واقعی
* ترافیک VPN بدون تغییر کانفیگ مشتری‌ها به Xray می‌رسد
* SSL با DNS-01 کلودفلر، صدور و تمدید خودکار (بدون نیاز به پورت ۸۰)
* فایل‌های آپلودشده بعد از N روز خودکار پاک می‌شوند
* همه‌چیز داکری — کپی پوشه روی نود جدید = نصب در کمتر از ۲ دقیقه

---

## نصب روی سرور جدید (یک دستور)

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/sepehrwwe49/filevault-node/main/setup.sh)
```

بعد از آن منو باز می‌شود. دفعات بعد فقط:

```bash
sudo fv
```

## معماری

```
                    :443 (TCP خام)
                          │
              nginx stream + ssl_preread
                   (تشخیص SNI)
                 ┌────────┴────────┐
      SNI ریلیتی │                 │ بقیه SNIها
                 ▼                 ▼
    127.0.0.1:12000        127.0.0.1:8443  (nginx https)
    Xray Reality                   │
    (خام، دست‌نخورده)               ├── /<path> ─► 127.0.0.1:12001  Xray XHTTP
                                   └── بقیه     ─► سایت آپلود (PHP-FPM)

    :2053 ─► پنل پاسارگاد (اصلاً لمس نمی‌شود)
    :80   ─► ریدایرکت به https + پشتیبانی XHTTP روی پورت‌های http کلودفلر
```

Reality به صورت **خام** پاس داده می‌شود → هیچ تغییری در کانفیگ Reality لازم نیست.
XHTTP پشت nginx می‌نشیند → nginx باید TLS را ترمینیت کند.

## سوییچ بدون قطعی برای مشتری‌های فعلی

کانفیگ کلاینت‌ها **هیچ تغییری نمی‌کند** — همان دامنه، همان پورت ۴۴۳، همان path.
فقط باید پورت ۴۴۳ روی سرور از Xray به nginx منتقل شود. روش کم‌ریسک:

1. **بک‌اند را بدون اشغال ۴۴۳ بالا بیاور** — منو → ۱ (ویزارد) → «بله» به سؤال آخر.
   گواهی SSL همین‌جا با DNS-01 صادر می‌شود، بدون دست زدن به پورت‌های وب.
2. **در پنل، اینباند دوم بساز** (کپی دقیق اینباند فعلی) روی
   `127.0.0.1:12001` برای XHTTP با **TLS خاموش**، و `127.0.0.1:12000` برای Reality.
   اینباند قدیمی روی ۴۴۳ را **دست نزن** — مشتری‌ها هنوز روی آن هستند.
3. **منو → ۲ (preflight)** — باید هر دو پورت جدید LISTEN باشند.
4. **منو → ۳ (سوییچ)** — اسکریپت منتظر آزاد شدن ۴۴۳ می‌ماند.
5. حالا در پنل اینباند قدیمی ۴۴۳ را غیرفعال کن. اسکریپت در کمتر از یک ثانیه
   nginx را روی ۴۴۳ می‌نشاند.

نتیجه: مشتری‌ها فقط یک **ری‌کانکت خودکار چندثانیه‌ای** می‌خورند (همان رفتاری که
هنگام ری‌استارت نود دارند)، نه قطعی واقعی و نه نیاز به آپدیت کانفیگ.

اگر چیزی خراب شد: **منو → ۱۶ (rollback)** → nginx خاموش، ۴۴۳ آزاد،
اینباند قدیمی را در پنل برگردان.

## منو

| گزینه | کار |
|---|---|
| ۱ | ویزارد نصب/تنظیمات (دامنه‌ها، پورت‌ها، path، توکن CF، حجم، مدت نگهداری) |
| ۲ | preflight — چک پورت‌ها و توکن قبل از سوییچ |
| ۳ | سوییچ بدون قطعی → nginx روی ۴۴۳ |
| ۴ | وضعیت نود + وضعیت پورت‌ها + حجم فایل‌ها |
| ۵ | افزودن/حذف دامنه و ساب‌دامنه |
| ۶ | SSL: وضعیت، صدور مجدد، تمدید اجباری، تغییر توکن |
| ۷ | تغییر پورت‌ها و path ایکس‌ری |
| ۸ | تنظیمات سایت: سقف آپلود، مدت نگهداری، نام سایت |
| ۹ | فایروال UFW |
| ۱۰–۱۲ | ری‌استارت / ری‌لود / لاگ‌ها |
| ۱۳ | self-test (صفحه اصلی، robots، sitemap، ۴۰۴، آپلود تستی) |
| ۱۴ | پاک‌سازی دستی فایل‌های منقضی |
| ۱۵ | بکاپ برای انتقال به سرور جدید |
| ۱۶ | rollback |
| ۱۷ | به‌روزرسانی از گیت‌هاب |
| ۱۹ | حذف کامل |

بدون منو هم کار می‌کند:

```bash
fv status | fv preflight | fv cutover | fv rollback | fv reload | fv test | fv backup
```

## تغییر پروتکل در آینده

هیچ‌چیز به پروتکل وابسته نیست:

* پروتکل با **TLS خودش** (Reality و مشابه) → دامنه‌اش را در منو → ۵ → «افزودن دامنه Reality» اضافه کن.
* پروتکل **پشت nginx** (WebSocket, gRPC, HTTPUpgrade, XHTTP) → منو → ۷ → path و پورت را عوض کن.

## ساختار

```
setup.sh              نصب یک‌خطی (کلون + داکر + منو)
menu.sh               منوی اصلی  (fv)
lib/core.sh           توابع: رندر کانفیگ، preflight، cutover، SSL، فایروال
.env                  تنظیمات این سرور (در گیت نمی‌رود)
docker-compose.yml    nginx + php + certbot + cleaner
nginx/                nginx.conf (stream+http)، تمپلیت‌های vhost و مپ SNI
site/                 سایت آپلود PHP بدون فریم‌ورک + robots/sitemap/terms/privacy/404
cleaner/cleanup.sh    حذف فایل‌های منقضی (هر ساعت)
cleaner/certbot/      صدور و تمدید SSL با DNS-01 کلودفلر
data/                 فایل‌های آپلودشده (بکاپ لازم ندارد)
```

## نکات امنیتی

* `.env` شامل توکن کلودفلر است — در `.gitignore` هست، **هرگز کامیت نکن**.
* توکن CF فقط با اسکوپ `Zone:Zone:Read` + `Zone:DNS:Edit` روی همان زون‌ها ساخته شود.
* فایروال (منو → ۹) فقط SSH، ۸۰، ۴۴۳ و پورت پنل را باز می‌گذارد.
